## Implemented code vs remaining runtime integration

- Existing HMAC verification remains before JSON use; raw body is bounded64KiB. GitHubSource validates repository ID and delivery GUID for every event type. Header event/delivery values are not authenticated by GitHub's body HMAC; no timestamp freshness claim is made.
- Existing logged ingestion preserves raw-byte verification, redacts all strings, omits unverified/malformed bodies, bounds retention/size and scopes reads by authenticated tenant. It logs every attributable attempt separately from receipt dedup. Some uncommon event header names are currently omitted by the log's conservative enum rather than stored unvalidated.
- Existing SQL receipts deduplicate tenant+configured source+delivery ID; conflicting hashes fail and concurrent identical requests accept once. No exactly-once downstream guarantee. SourceId now propagates to receipts/event identities, replacing fixed github; this is a predeployment change, not a live receipt migration.
- PolicyPipeline is a PURE PREVIEW engine: deterministic unique order and stage IDs, original/payload separation, stage data, bounded results/deadlines, fail-closed errors/denials, and registered tenant destination-ID validation. It performs no network or outbox writes. Optional transformations are composable, not a mandatory first-slice stage.
- OpaRouteStage uses the real bounded official OPA process. Input is schema_version, trusted context, original, payload, enrichments (empty for first slice), and destinations [{id,name,tags}]. No URL, auth reference, token or another tenant's metadata appears in that input. OPA returns destination_id+payload; router validates selected IDs and limits. Existing MCP subscription_id evaluator stays separate.
- SqlDestinationReader queries only enabled tenant metadata and demands destinations:read. destination-schema.sql is an explicit optional migration, not applied automatically or live. It has IDs/names/tags/enablement and no URL/auth fields. SQL permissions for this new table are not silently added to already-provisioned identities.
- GenericRouting opt-in now connects HTTP ingestion to GenericIngestion: one registered OPA policy (none means deny; more than one is a configuration error), tenant metadata snapshot, validation and transactional generic outbox. Existing generic-mode off preserves the legacy MCP path. No deployed settings were changed.
- delivery.DestinationConfig privately stores immutable endpoint/signing-key references; SqlDestinationResolver enforces tenant/scope and current enablement. delivery.WebhookOutbox is separate from MCP event envelopes. GenericDeliveryProcessor claims, resolves privately, signs, completes or retries with bounded attempts; failed/disabled targets cannot silently become MCP deliveries.
- SafeWebhookTransport validates HTTPS443 DNS URLs, forbids embedded auth/query/fragment/IP literals, disables redirects/proxy, rejects nonpublic DNS answers and pins the TCP connection to a validated address while leaving normal TLS hostname validation enabled. Controlled local HTTPS tests now exercise exact signed receipt, invalid certificates, redirects and DNS pinning; no external delivery was performed.
- Queue/timer dispatch, protected setting secret resolution and tenant-scoped destination MCP tools are implemented; deployment prerequisites and hosted E2E remain outstanding. See the activation handoff for exact permissions and disabled-by-default flags.

## Next implementation boundary

The implementation includes a tenant-bound destination registration service with stable ID, bounded name/tags and separately protected target configuration. Management operations need explicit destinations:write; policy and Jev inputs can read metadata only. Protected endpoint/auth resolution is inside the dispatcher; never pass credentials into evaluator arguments or logs. Name/tag fields must not contain credentials. DestinationConfig updates are blocked by a SQL trigger; application grants must allow INSERT/SELECT only, no DELETE/UPDATE, so an endpoint change requires a new destination ID. Metadata can disable old IDs. An administrator can override SQL protections; app identities must not have DDL/owner authority. Versioned management APIs remain future work.

Generic deliveries are now persisted separately from MCP event-envelope deliveries, with transactional receipt/outbox records and bounded attempts. Resolve destination ID under the same tenant again at send time. For each approved HTTPS URL enforce no embedded credentials/fragments, approved ports, no redirects, public-address DNS checks including IPv4/IPv6 and rebinding protection that pins the connection to validated addresses while preserving TLS hostname validation. Reject loopback/private/link-local/metadata/reserved ranges. Controlled local HTTPS tests pass on Linux; Windows CI and hosted validation are tracked separately. This is not production verification.

Current generic limits:16 destinations,64KiB output per destination,256KiB OPA input,1.1M-character OPA stdout,5 delivery attempts. Set independent admission/rate budgets before live usage. Use independent signature credentials per configured delivery target; never reuse GitHub ingress secrets by default. Generic webhook payload is the chosen/transformed event data, not automatically an MCP Events envelope. The proposed generic protocol signs exact body bytes as X-Webhook-Signature-256: sha256=<hex> and sends X-Webhook-Delivery with the stable event ID. Confirm receiver compatibility before activation. Callback failures remain in durable queue, and receiving systems deduplicate delivery IDs.
