# Next hosted POC gate

The existing dedicated webhook-mcp-router-ci token, already approved and saved as repository secret WASMER_TOKEN, authorizes account-level deployment only. It must never become an MCP bearer token or a webhook signing key.

Prepared files: deploy/app.yaml (one WCGI app, two tiny synthetic volumes), deploy/wasmer.toml, ci/build-hosted.sh. They have not deployed anything. The package uses the existing pinned WASIX Go release and standard nonblocking Dialer.Control; Nix expressions remain untested, and the CI image CA bundle is not yet independently pinned. The release build requires committed module locks and readonly resolution.

Before a secure hosted test, approve creation of three isolated synthetic app secrets: POC_TEST_TOKEN (MCP bearer), POC_RECEIPT_TOKEN (receipt readback bearer), and POC_WEBHOOK_SECRET (Standard Webhooks synthetic key). Requested scope is one isolated synthetic E2E session; revoke immediately after testing, with a maximum operational lifetime of 24 hours. This is an approval proposal, not an already enforced expiration or cleanup schedule. Keep these in Wasmer secret storage and the protected GitHub environment used by the E2E job, never source, package files, logs, or the existing Wasmer API token. No secret has been generated or provisioned for hosting. Local ephemeral test values are not reusable hosting credentials.

Also verify this app's actual HTTPS endpoint, then set POC_CALLBACK_URL to its /callback route and the CI endpoint variables. No caller-controlled destinations are permitted. Do not assume a guessed app hostname is owned by this deployment. Existing free allowance and volume eligibility must be confirmed before creating resources; no paid upgrade, new external database, or billing change is authorized.

The persistent volume is a deliberately limited synthetic registration fixture, not the required production shared database. Ingestion calls only read methods; MCP manages writes. There are no separate database credentials or enforceable RO/RW connections yet. Wasmer documents single-region read-write-many volumes and cautions against database-style single-writer assumptions. Fresh-instance readback on a local mapped filesystem does not prove Edge rename/exclusion/concurrency semantics. Hosted testing must check those semantics before making persistence claims.
