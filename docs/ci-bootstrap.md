# CI preparation and secure bootstrap

Build workflow: PR/push/manual, read-only contents permission, no secrets, pinned official checkout/setup-go actions, Go 1.27.3, digest-checked Wasmer 7.5.0. It runs the generic CGI guest assertion, resolves/verifies modules, tests the real fork and attempts its WASI build. Failures remain failures. This discovery run may change module sums locally; review and commit complete go.mod/go.sum before release. It is not a reproducible Nix release yet.

Deployment workflow: manual only, default branch only, serialized, 20-minute limit, `wasmer-poc` protected environment, explicit no-spend confirmation. It fails before any deployment while `ci/hosted-readiness.json` is false. This is deliberate: the current loopback-only, in-memory prototype cannot safely serve the requested hosted lifecycle. Flipping the flag alone is not sufficient: reviewed manifests, authenticated WCGI entrypoint, durable state, outbound transport, Nix build and controlled sink must exist and pass review first.

## Bootstrap sequence (not performed)

1. Create approved PUBLIC `r33drichards/webhook-mcp-router`; publish only audited project files, never `.tools`, caches, credentials or raw signed download URLs. Repo name/visibility are approved; the connector lookup currently returns 404 and exposes no repo-create action.
2. Repository owner/admin configures environment `wasmer-poc`: selected default branch only, required reviewer, prevent self-review and disable admin bypass where supported. Protect default branch and review workflow/script changes. GitHub public repositories support these protections on current plans; verify the actual plan before configuration. Workflow YAML alone does not create protection rules.
3. Verify Wasmer account/namespace ownership, free allowance, intended app name, storage eligibility and GitHub runner allowance. Public Hobby pricing does not prove this account has unused allowance. No paid resource/upgrade or billable overage is authorized. Keep deployment disabled if a zero-spend bound cannot be established. A job timeout limits CI duration, not hosted lifetime or cost; agree on app cleanup after testing.
4. Wasmer authentication still needs bootstrap. Official CLI supports interactive `wasmer login` and reads `WASMER_TOKEN`; `deploy` also reads the token directly, so CI does not need a persisted login. An authorized account owner must choose an existing credential with sufficient namespace/package publication and app-deploy access. If a new token, grant, or broader role is required, stop for explicit approval; token scope granularity has not been verified. Never use a token exposed in chat. Store an approved credential only as environment secret `WASMER_TOKEN`, not a repository file/variable/command argument. No OIDC flow is assumed.
5. Configure the reviewed synthetic service's management credential and fixed sink separately from the deploy credential. Environment secrets `POC_TEST_TOKEN` and `POC_RECEIPT_TOKEN` authorize only test calls and receipt reads. Environment variables `POC_MCP_URL` and `POC_RECEIPTS_URL` contain reviewed HTTPS endpoints without embedded credentials. Do not use the Wasmer token as app authentication. New secret creation/configuration remains a bootstrap approval question, not something performed here.
6. Complete and review `deploy/app.yaml`, `deploy/wasmer.toml`, and `ci/build-hosted.sh`. Use the existing pinned Nixpkgs revision in `spike/nix/pins.json`, pin/verify Nix bootstrap and Go toolchain, and calculate a real vendorHash after complete dependency resolution. No fake hash or floating installer. Nix is absent locally; no Nix build was validated. Commit readonly module metadata; the release script must test/build the official SDK implementation and emit `deploy/server.wasm` from reviewed sources.
7. Run build CI on the normal GitHub runner network without changing this environment's denied routes. Review failures before enabling release. Set readiness true only in a reviewed implementation change. Dispatch the deployment workflow after account/cost/security review. Exact CLI used is `wasmer deploy --dir deploy --non-interactive --publish-package --no-persist-id`, verified in installed 7.5.0 help; this publishes the package and deploys the app, with owner/name supplied by the reviewed manifest. No `--no-validate` or remote build is used.
8. `ci/hosted-e2e.py` requires actual HTTPS initialize, tools/list, tools/call create, readback on a separate request, synthetic emit, controlled sink receipt and cleanup. It rejects session IDs, requires JSON responses, and fails without a signed receipt matching event/subscription/nonce. The POC-specific tools/receipt schema in that script are POC-specific fixture methods now implemented in `spike/hosted`, but their SDK integration remains uncompiled and untested; they are not the events extension itself. Server WCGI configuration must establish fresh invocation semantics; separate client connections alone cannot prove server process replacement. The sink must independently verify the real signature before returning `signature_verified: true`.

The real events extension must still match the inspected WeeChat source: events/list, events/subscribe and events/unsubscribe, webhook delivery registration, verification challenge and signed event envelope. Tool-based synthetic testing does not prove exact extension compatibility. SDK stateless JSON source support does not prove hosted behavior.
